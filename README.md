# Montage

A professional non-linear video editor written in **C++20** with **Qt 6** and **FFmpeg**.

It covers editing, colour, audio, captions, multicam, interchange and delivery in one application,
with on-device AI tools, a command-line renderer and an MCP server for AI agents. Open-source editors
such as Kdenlive, Shotcut and Olive also build on C++, Qt and FFmpeg.

## Features

**Editing**
- Multi-track timeline: unlimited video and audio tracks, with lock, sync-lock, mute, solo, hide and track targeting
- Tools: Selection (V), Razor (C), Ripple (B), Roll (N), Slip (Y), Slide (U), Hand (H)
- **Trim mode** (keyboard trimming): `Shift+T` selects the edit nearest the playhead on the target video track, `Alt+T` switches between both sides (a roll), the outgoing side and the incoming side (ripple trims), and `Ctrl+Left`/`Ctrl+Right` trim a frame at a time (five with `Shift`). Red brackets mark the sides being trimmed, the playhead and the two-up view follow the edit, each trim is one undo step, and `Esc` ends it.
- **Two-up trim view**: while an edit is trimmed, rolled, slipped or slid, the Program monitor shows the frames either side of it side by side, each labelled with its clip and timecode (a slip shows the clip's first and last frames). Playback › Two-Up Trim View turns it off.
- Insert, overwrite, lift, extract, ripple delete, close gap, nudge, duplicate, copy / paste / paste-insert. **Gaps**: click the empty stretch between two clips to select it and press Delete to close it, rippling what follows. A selected gap can also be copied or cut (closing it) and pasted at the playhead as that much empty space, splitting a clip there and pushing what follows on sync-locked tracks.
- **Transition handles**: drag either edge of a dissolve on the timeline, or a fade's edge away from the cut, to make it longer or shorter, with its length shown as you drag. A dissolve stays centred on the cut and inside both clips; one undo step.
- Three-point editing from the Source monitor (I / O marks, `,` insert, `.` overwrite, drag from the viewer)
- **Reverse Match Frame** (`Shift+R`; Clip menu): the frame showing in the Source monitor, found in the sequence: the playhead goes to it and its clip is selected. Pressed again it steps to the next place that frame is used (any track, at any speed or reversed), round to the first. Match Frame (`F`) goes the other way, through nested sequences and multicam clips (their angle) to the file underneath.
- **Compare with Sequence** (Sequence menu): duplicate a sequence before a round of changes, then compare the two versions. A list shows each clip added, removed, trimmed (its in and out points in source frames), moved (to another track, or changed places with its neighbours) or changed (speed, effects, picture, sound, a title's text); clips that only slid along with the edits around them are left out, and a clip's linked sound is not listed twice. Double-click to go to a change; **Add as Markers** puts a coloured marker on the sequence for each one (one undo step). MCP `montage_compare_sequences`.
- **Change lists and re-conform** (Compare with Sequence › Change List): the new cut's picture matched frame by frame to the old one's, as events: stretches kept in their old order (and how far they slid), moved, inserted, extended, deleted and trimmed. **Export Change List** writes a change EDL (CMX 3600, the old cut as reel OLDCUT and new material as NEWCUT, for Pro Tools and VFX conform tools) or a CSV. **Re-conform** rebuilds a sequence cut to the old version (the sound mix, the grade, effects and titles over it) to play against the new one: every track's clips, transitions and fades, track and bus automation, markers and captions carried to where the new cut plays them, new material filled in from the new cut (labelled), markers on what was added and taken out; one undo step. MCP `montage_reconform`.
- **Conform Check** (Sequence menu): a sequence built from an XML, AAF or EDL laid against the offline cut's reference movie, shot by shot. Each shot matches, is **reframed** (the reposition the list lost, solved from the reference as scale, rotation and position, keyed every 12 frames when it moves, at most 25 keys a shot; flips, crops, Fit and width/height scales kept), **slipped** (by how many frames), **another take** (found among the scene's media, or all of it when the clip has no scene), **missing** (a gap where the reference has a picture) or matches nothing near. Grades do not count (each picture is normalised before comparing) and the reference's burnt-in timecode, watermark or letterbox is masked out by itself (what stays the same across its shots). Double-click a shot to go to it; **Apply Fix** puts the selected shots right and **Apply All** every one that can be (the take swapped with its linked sound, the slip, the Transform), **Add as Markers** marks the rest; each one undo step. MCP `montage_conform_check` (`apply`, `markers`).
- **Selection readout**: the status bar shows how many clips are selected and how long they run, first start to last end.
- More source edits (Clip menu): **Append at End** (Shift+F12), **Place on Top** (F12: the first tracks above the target with room, new ones if none, nothing below moves), **Ripple Overwrite** (Shift+F10: the clip under the playhead becomes the source range and everything after moves by the difference) and **Smart Insert** (insert at the edit nearest the playhead, so a cut never lands mid-clip). The MCP `montage_place_media` tool takes the same as `mode`.
- **Source monitor waveform**: a clip with sound shows its audio waveform on the Source monitor's scrub bar, so a line or a beat can be marked by eye
- **Record Voiceover** (Sequence menu, Ctrl+Alt+R): record from any audio input onto an audio track where the playhead is, with a level meter and a 3-second countdown, while the picture plays along. Punch In records from In to Out and stops by itself. Each take is saved as a WAV in a Voiceover folder beside the project, filed in the media bin and placed on the track as one undo step.
- **Takes on lanes**: Record Voiceover's Loop records from In to Out again and again while the picture loops, each pass a take lane under the track (a pre-roll heard once first). Sweep across a lane to give that stretch to the comp, with a short equal-power crossfade at every join; moving a join moves both sides. Lanes are named and rated, an audition's other takes (ADR takes too) show as lanes, and the ADR panel's Best Take suggests the take whose words best match the line. Track Versions in the track header's menu keep whole other edits of a track to switch between. The comp is ordinary clips, so it mixes, exports and goes to AAF as it plays. MCP `montage_takes`.
- **ADR (dialogue replacement)** (Sequence › ADR, a panel beside the Program monitor): a cue list kept with the sequence (cue number from the character's initials, character, line, a note on why, start, end, status: To Record, Recorded, Approved, Omitted), made from captions (a speaker label like "ANNA:" or "[Anna]" is the character), range markers, In to Out, or a cue sheet (CSV or tab separated, Pro Tools-style column names, timelines from 01:00:00:00 understood), and written back out as a cue sheet. **Rehearse** plays a cue's cycle: pre-roll, three 1 kHz beeps a second apart with the line where the fourth would be, a white streamer crossing the picture to the line, a punch on its first frame and the line itself over the picture. **Record** plays it again and records the actor (the guide track muted if wished, and the takes already made), each take landing as a take of one audition clip over the line on an ADR track (overlapping lines on ADR 2, 3...), in sync, the newest the pick, a take stopped before the line not kept; **Loop** records take after take until stopped. Takes are picked from the panel or like any audition. **Align to Guide** fits the chosen take (or a converted voice) to the guide's timing over the line, its pitch kept: both are compared as speech (the broad shape of the spectrum and the rhythm of the level, so a different voice still lines up) and the take is stretched and squeezed, pauses most, to land on the guide's syllables; a Dialogue Alignment effect on the take (cached like Noise Reduction, undone or removed like any effect). Prefer Shifting lines up another microphone of the same take with the boom by moving it alone, to a fraction of a sample, its polarity put right (MCP `montage_align_dialogue`, `mode: shift`). MCP `montage_adr` (list, add, from captions or markers, update, cue sheets, add and pick takes); re-conforming a sequence to a new cut carries its cues along.
- **Audio description** (described video, as broadcasters and streaming services ask for; Sequence › Audio Description): finds the gaps between the dialogue (the Dialogue clips, or every clip but music and effects, kept clear of the lines), lists them with the descriptions written into each and whether each fits at a describer's pace (how many words to cut if not), voices them with the AI voices onto an AD track as clips of the role Description (a little faster where a gap is short), ducks the programme under them (on a lane of its own, heard only with the descriptions, so the mix without them is never dipped), and mutes them while working if wished. **Draft From the Pictures** writes a first draft into each empty gap from the picture in its middle, on this computer: Florence-2 says what it shows and the language model words it as a describer would (present tense, what is seen, people by how they look rather than by a name the picture model guessed), held to the words the gap has room for at the pace set (or, with the language model off, the picture's brief caption); every draft fits its gap, and is meant to be read through and corrected. Export's audio description option writes the mix without the descriptions and a second stream, "Audio Description", of the programme with them (levelled like the mix, marked for the visually impaired; containers with several streams only, never stems). MCP `montage_audio_description` (gaps, write, draft, list, voice, duck, hear) and `montage_render` `described`.
- **Track folders**: right-click a track header › Folder to put tracks in a new or existing folder. A folder's header collapses its tracks (their clips shown in outline on its row), and its M and S (or ◉ for video) buttons mute, solo or hide all of them; member tracks carry an amber stripe. Rename or remove a folder from its header's menu. An audio folder also gets a **VCA fader** in the Audio Mixer: its level is added to each of its tracks' faders in the mix and in exports, so a group of dialogue tracks can be ridden together. Saved with the sequence.
- **Sidechain keying**: the Compressor and Noise Gate, on a clip or a track's inserts, can listen to another audio track instead of their own signal (Inspector › Sidechain), so music ducks under dialogue as it is spoken or a gate opens on a kick, with a high-pass on what they listen to (Key High-Pass). Third-party plugins with a key input (CLAP's second input port, a VST®3 auxiliary bus, LV2 side-chain ports) get the same Sidechain choice, so a plugin compressor, gate or ducker hears the chosen track there (silence when none is chosen). The key is the track before its fader and is heard even when that track is muted. MCP `montage_track_effect` adds track inserts with `{"sidechain": "A2"}`; `montage_add_effect` takes it too.
- **Card offload with ASC MHL** (File › Offload Card): copies a camera card to one or more drives at once, each file read once while it is checksummed (XXH64), every copy read back past the system cache and compared, modification times kept, OS junk left behind. An interrupted offload resumes (identical files kept, different ones reported, never overwritten). Each copy gets an ASC MHL v2.0 generation (the Academy's media hash list, with folder and root hashes and the chain file) that the ASC's own `ascmhl` tool verifies; a card that already carries a hash list is checked against it and its history goes with the copy. The copied media lands in a bin named after the card. File › Verify Media Hash List checks any folder against its ASC MHL history, whoever wrote it, and can record a new generation. MCP `montage_offload`, `montage_verify_mhl`.
- **Recovering interrupted recordings** (Media bin › Repair Media; `montage-cli repair`, which writes over an existing file only with `--overwrite`): a recording the camera or recorder never finished, after a flat battery or a pulled card, rebuilt into a new file beside it. An MP4 or MOV without its index is rebuilt from a good clip from the same camera: its sample descriptions are kept, and the media data is walked sample by sample (H.264 and HEVC by their NAL units, ProRes by its frame header, PCM by the camera's chunk sizes, AAC by trial decoding), with backtracking where a guess goes wrong and a skip past damaged bytes, and a new index written with the display order the decoder gives. An MXF without its footer gets a closed header with the true duration, an index table and a random index pack; a WAV, BWF or RF64 whose sizes were never written is fixed from the file's length (RF64 past 4 GB), keeping bext and iXML. The repaired file is imported with the keyword Recovered and the start timecode a Sony or P2 sidecar gives. Importing a file like this offers to repair it, and Offload Card names the copies that need it. MCP `montage_repair_media`.
- **Out-of-sync indicators**: a linked clip that has slipped out of step with its picture (moved or slipped on its own, same media at the same speed) shows the frames it is late (+) or early (-) in a red box on its name strip; right-click for Move into Sync (moves it back) or Slip into Sync (slips its source in place, refused past the media's ends). Quality Check lists out-of-sync clips; MCP `montage_sync` (check, move, slip) and `montage_quality_check` `sync`.
- **Through edits**: a cut the picture or sound runs straight through (what a razor cut leaves: the same media continuing at the same speed with no transition) gets a small white arrowhead, and Clip › Join Through Edits puts the selected clips (or the whole sequence) back together with their linked sound, as one undo step.
- **Clip durations** (Sequence › Show Clip Durations): each clip's length as timecode in its name strip, where the clip is wide enough.
- **Normalise Waveforms** (Sequence menu): each audio clip's waveform drawn to the full height from its own loudest point, so quiet dialogue and room tone are readable; the clip's level no longer scales the drawing.
- **Duplicate frame markers** (Sequence › Show Duplicate Frame Markers): video frames used more than once in the sequence get a stripe along the bottom of each clip that repeats them, one colour per file, so a reused shot is caught before delivery. Speed changes are followed; sound and titles are not counted.
- **Close Up** (Clip › Close Up): a punched-in copy (150 %) of the video clip under the playhead, over In to Out or the whole clip, goes on the track above, framed on the face found in it (YuNet, with the People model installed) or else on the middle, without uncovering the frame's edges.
- **Layouts** (Clip › Layout): the selected video clips, or every video clip under the playhead, share the frame. **Side by Side**, **Top and Bottom**, **Three Across** and the **2 × 2 Grid** fill each cell (cropped from the middle, the lowest track first); **Picture in Picture** keeps the lowest clip full frame and puts the others, whole, in the corners at 30 % of the width; **Full Frame** puts them back. One undo step, ordinary scale, position and crop you can then adjust or animate. MCP `montage_layout` adds a gap between cells, the corner and the inset's size.
- **Auditions** (Clip › Audition): select a clip and the alternative takes in the Media bin (or one in the Source monitor from its In) and choose Add Selected Media as Takes (Ctrl+Alt+Y). Ctrl+Alt+Right and Left then try each take in the clip's place, keeping its length, effects and keyframes, with linked sound following; the clip shows "take 2/3". Trims and splits carry the takes along. Finalize Audition keeps the pick. Saved with the project; Project Manager keeps every take's media. MCP `montage_audition`.
- Ripple Trim Previous / Next Edit to Playhead (Q / W), Select Clips After Playhead (A, Shift+A on the target track), Replace with Source Clip, Fit to Fill, Add Frame Hold (Shift+F; Time Remapping can also go to 0 % to hold mid-ramp), and Swap with Previous / Next Clip (Ctrl+Shift+, and Ctrl+Shift+.: a clip and its neighbour change places with their linked sound, and a dissolve between them moves to the new edit; MCP `montage_swap_clip`)
- **Extend Clip**: Clip › Extend Clip › By 1 Second, By 2 Seconds or To the Playhead carries a shot on past the end of its media. The last frame is held while the camera's motion over the shot's final half second (a pan, a drift, a push or a turn, measured by tracking its texture) carries on and eases to rest, scaled up just enough as it drifts that the frame stays filled, and its linked sound gets the room's own tone; what follows is pushed along, all in one undo step. MCP `montage_extend_clip`.
- **Delete Gaps**: Edit › Delete Gaps closes every stretch of the timeline where no track has anything, so nothing slips out of sync (a picture gap over continuing sound stays); what follows moves up with its captions, markers, In/Out and track automation, in one undo step. Gaps a locked track's clips would have to cross stay. MCP `montage_delete_gaps` (optionally the empty start too).
- Paste Attributes (Ctrl+Alt+V) and Remove Attributes: motion, opacity and blend, Time Remapping, volume and effects, keyframes included
- Synchronise clips from separate cameras and recorders by audio waveform (cross-correlation, sub-frame accurate)
- **Timecode from LTC** (Media bin › Timecode from LTC): linear timecode (SMPTE or EBU LTC, 23.976 to 30 fps, drop frame too) that a timecode generator feeds into a camera's or recorder's sound channel is found on whichever channel carries it and becomes the file's timecode, to a few microseconds, sound files included; the file's own is kept (Use the File's Own Timecode). The LTC channel stops being played by the file's clips and new clips leave it out, and Merge Clips, Sync Dailies and multicam sync by timecode use it. Sequence › Add LTC Track writes the sequence's own timecode as LTC on a new, muted audio track (unmute it to send timecode out). `montage-cli ltc file.mov` reads it (`ltc -o ltc.wav --start 01:00:00:00 --duration 60` writes it); MCP `montage_ltc`.
- Linked audio/video, linking and unlinking, snapping, markers, match frame, compound (nested) clips
- **Stacked Timeline** (its own panel, or Media bin › Open in Stacked Timeline): another sequence shown read-only beside the one you edit. Select clips or mark a range with I and O, and drag them onto the timeline (Ctrl inserts); they keep their tracks, spacing, links and transitions. Swap trades the two. **Clip › Insert Sequences as Clips** makes source edits and drops from a sequence (a selects reel in the Source monitor, say) bring its own clips between the marks rather than one nested clip.
- **Timeline tabs**: each sequence opened (from the bin, or made new) gets a tab above the timeline; click to switch, drag to reorder, close to put away (the last one stays open). Tabs follow renames.
- **Marker lists** (Sequence › Export / Import Markers, MCP `montage_export_markers` and `montage_import_markers`): export the sequence's markers as a CSV in Premiere Pro's marker-list layout, as Avid Media Composer locators, as a marker EDL that DaVinci Resolve imports, or as a PDF with a picture of each marker's frame for a review or a client; import notes from a CSV (review tools' Timecode/Comment exports work) or Avid locators, as one undo step. Lists made on timelines that start at 01:00:00:00 are moved to the start.
- **Clip markers** (Sequence › Add Clip Marker, `Shift+Alt+M`): a marker on the selected clip at the playhead, kept on that moment of its media, so it travels with the clip through moves, trims, speed changes and splits. Drawn as flags on the clip, listed in the Sequence Index (renamable), saved, and carried by OpenTimelineIO (on the clip) and FCPXML (inside the clip; chapter markers as `chapter-marker`). MCP `montage_add_marker` with `clip`.
- **Changed media reload by themselves**: a still re-saved in Photoshop or a graphic re-rendered is picked up while you work: its cached frames, thumbnail and sound are dropped, its size and length re-read, and the monitors redrawn. **Edit Original** in the bin's context menu opens a file in its own application.
- **Interpret Footage** (right-click videos or stills in the media bin, or MCP `montage_interpret_media`): how a file is read, for every clip made from it. **Frame rate**: each of the file's frames shown for 1/rate of a second, so 120 fps footage assumed at 24 plays five times slower as smooth slow motion and 25 fps material conforms to 23.976; its sound conforms with it, at the new speed (varispeed) or with **Keep the audio's pitch** time-stretched to the new length. **Pixel aspect ratio**: the file's replaced (square, the D1/DV and HDV ratios, anamorphic 1.33x, 1.5x, 1.65x, 1.8x and 2x, or any value), so an unflagged anamorphic shot is shown desqueezed. **Alpha**: straight, premultiplied, ignored or inverted. **Field order**: progressive, upper or lower first whatever the frames are flagged, to deinterlace footage marked progressive or leave alone footage that is not interlaced. **Pulldown**: 2:3 pulldown removed from 29.97 or 30 frame video made from 23.976 or 24 frame pictures (film or a 23.976 camera through a telecine), its fields woven back into the original frames so it plays at 23.976 or 24 with no combed or repeated frames; the cadence is found from the fields, stretch by stretch, so video edited after the pulldown (which breaks the cadence) is undone across the break, or you say which frame it starts on (A to D). Clips keep starting on the same frame and keep their length on the timeline; subclips, clip markers, transcripts and the shot and face indexes keep to the same frames; one undo step. The interpretation travels with the media, so thumbnails, waveforms, proxies, analysis, exports, relinking and Project Manager copies all read it the same way.
- **Offline media and Link Media**: media whose files have moved show as **Media Offline**, a red slate in the monitors and red clips and tiles, and opening such a project brings up **Link Media**. Locate one file and the others are looked for beside it, or search a folder (and the folders inside it) for all of them; a file must be the same footage (kind, picture size, length) and a transcode is found by its name with another extension (A001.mxf as A001.mov). Each relink is one undo step and keeps the item's logging, transcript and clips. **Replace Footage** (the bin's context menu) swaps in a different file under the same clips. File › Link Media opens it any time; MCP `montage_relink`.
- **Growing files**: a file still being written (a recorder, a capture card or a render that has not finished, in a format that can be read while it grows: MXF, fragmented MOV and MP4, MPEG-TS, WAV) is noticed as it is written and shown with a red GROWING badge; its length, pictures and sound are read again every 15 seconds (or 5, 30, 60, or only once it stops: the bin's Growing Files menu), in the background, so its clips play, show their waveform and can be cut and trimmed further as the recording goes on, and once it stops it is reloaded in full (thumbnails too). A length read this way is a fact about the file, not an edit: undo keeps it, and the project is marked changed so it is saved. Clips already in a sequence keep their length. A file written on a network share by another computer is not noticed by itself (the system reports no writes): Growing Files › Refresh All Media Lengths Now reads every media file's length again, as does MCP `montage_refresh_media`, which an agent on the live link can call.
- **Project Manager** (File menu, MCP `montage_consolidate`): copies the project to a new folder with the media it uses, for archiving or handing on. **Collect** copies each used file whole; **Consolidate** transcodes only the parts of each video the sequences use, plus handles, to ProRes 422 HQ or H.264, and points the clips (and transcripts, moved to the new timing) at the new files. Keep all sequences or just the active one and what it nests; media nothing uses is left out unless you keep it; missing files are reported.
- **Merge Project** (File menu, `montage-cli merge`, MCP `montage_merge_project`): two copies of a project brought together from the version both started from, such as an assistant's bins and syncing, a colourist's grades or the work done on another computer. Project Manager copies and **Save a Copy for Another Editor** record that version, or you can choose it. Everything is compared field by field. Changes made on one side are taken, and the same change made on both is taken once. Different changes to the same thing are listed as conflicts, each settled as Mine or Theirs. Their clips that would overlap yours go on a new track until you choose Both, Mine or Theirs. Ids both copies made are renumbered. Double-click a change to go to it; the merge is one undo step.
- **Smart rendering**: exporting to ProRes or DNxHR, frames that are one untouched clip of footage already in the same flavour, size, sampling and rate are copied from the source file rather than decoded and encoded again: faster, and exactly the original pictures. Anything that changes the picture (an effect, a move, a transition, another layer, a burn-in, a colour conversion, proxies) is rendered as usual. On by default; an Export dialog option.
- **Chapter markers** (Sequence › Add Chapter Marker, `Alt+M`): drawn as orange flags; an ordinary marker at the playhead becomes one. They are written as chapters into exported MP4, MOV and MKV files (players and YouTube read them; an option in the Export dialog). **Copy Chapters for YouTube** puts the list for a video description on the clipboard ("0:00 Intro", "1:05 Setup", timed from In when In and Out are set) and warns when YouTube would not show it: fewer than three chapters, or one under ten seconds.
- Constant speed changes and reverse, with optional ripple
- Snapshot undo/redo for every operation; drags and slider edits merge into one undo step
- **Render cache**: Sequence › Render In to Out (Return) renders the frames between In and Out (or the whole sequence) as the Program monitor shows them, so heavy effects play in real time. A green render bar under the ruler shows what is rendered. Frames stay rendered until something that shows in them changes. Moving a clip keeps its frames, and undo brings them back. Sequence › Delete Render Files empties the cache. **Background Render** (Sequence menu, off by default): after a few quiet seconds, the stretches with effects, titles or transitions render by themselves off the UI thread; editing or playing stops it until the next quiet spell.
- **Sequence Index** (a panel beside the Media bin): every clip and marker in the sequence as a table, with its kind, colour label (a swatch and its name), audio role, track, start, end, duration, source In, media and effects. Type to filter on any column (a colour's name finds every marker and clip carrying it), click a header to sort, double-click a row to select the clip and go to it, and rename a clip or marker in place (one undo step).
- **Workspaces**: the panels laid out for a task. **Editing**, **Colour** (scopes beside a large Program monitor, the Inspector full height), **Audio** (the mixer where the Source monitor was, wide meters), **Effects**, **Captions** and **Logging** (a wide bin with Find Shots, People and the Transcript) are a click away in the bar at the bottom right, in Window › Workspaces or on Alt+Shift+1 to 6. Arrange the panels as you like and Save as New Workspace to keep the layout under a name; Reset Workspace to Saved Layout puts it back. The current workspace is remembered, and `montage --workspace Colour` opens in one.
- **Screen readers and the keyboard alone**: Montage's own widgets speak to VoiceOver, NVDA, Narrator and Orca through Qt's accessibility layer. The timeline is a table, a row a track, whose cells are its clips and the gaps between them ("A001_C003, V1, 00:00:10:00 to 00:00:14:12, Cross Dissolve out"), with the playhead and selection as its value; pressing a cell selects it. The monitors give their timecode, In and Out; meters their levels; the scopes a summary of the picture ("levels 4 % to 96 %, average 41 %; saturation 18 %, leaning blue"); the keyframes are a list ("Opacity, 00:00:01:00, 80, Linear"); mixer controls are named after their track ("A1 volume"), and other unnamed controls after their label, tool tip or panel. Each edit, undo and redo is announced with the clip it left selected. F6 and Shift+F6 move between the panels shown and the timeline, Ctrl+F6 brings the next panel tabbed with the focused one to the front; Alt+Up and Alt+Down select the previous or next clip on its track, Alt+Shift+Up and Alt+Shift+Down the clip at the same time on the track above or below, Shift+C the clip under the playhead. In the Keyframes panel Up and Down move between parameters, Alt+Left and Alt+Right between keys, Left and Right move the selected keys, Insert or Enter adds one at the playhead. The Media bin keeps the arrows and Enter for itself. Window › High Contrast (white on black, yellow focus, 7:1 or more) and Window › Text Size (100 to 200 %), kept between sessions. Announcements of edits need Qt 6.8 or later (the release builds); before it they are set on the status bar. Tested offscreen and read back over AT-SPI on Linux CI; VoiceOver and NVDA are not tested here.
- **Learned effects**: work done by hand on a few frames of a shot (a grade, paint, a logo removed) is learned and applied to the rest of it. Clip › Learn Effect from Examples… trains a small network (a 4-level U-Net, about half a million weights) on the clip's frames before and after its effects, on this computer's processor, in the background with a preview, stopped and continued at will; the result is a Learned Effect on the clip or the clips selected, saved beside the project and run through ONNX Runtime. Also from an agent (`montage_train_effect`).
- **Keyboard Shortcuts** (Help › Keyboard Shortcuts, F1): every menu command can take any key, found by name or key. A key already in use moves only after asking. Keys can be reset one by one or all together, and layouts can be exported to or imported from a JSON file. Presets: Montage (the default), and Premiere Pro-style, Final Cut Pro-style, DaVinci Resolve-style and Avid Media Composer-style shortcuts.
- Scene-cut detection that cuts a clip at every shot change

**Effects and colour**
- Transform on every clip: position, scale, rotation, anchor, crop, opacity, flip, and fit/fill/stretch
- **Motion paths**: an animated position shows its path over the Program monitor, a dot a frame so their spacing shows the speed and a square at each keyframe; drag a square to move that keyframe (one undo step) while the box still moves the clip at the playhead.
- **Expressions**: any keyframeable number setting of a clip can be driven by a short Lua formula (the **=** button beside its keyframe buttons, or Expression… on its menu), such as `value + wiggle(2, 10)`, `loopOut("pingpong")`, `param("Logo", "pos_x") + 50` (follow another clip's setting) or `100 * audio(1, "low")` (pulse with the bass).   - **Motion Blur**: on footage, each pixel is averaged along the path optical flow says it moves on while the shutter is open, set as a shutter angle (180° is film's usual; 360° doubles it).
  - **Deflicker** (for timelapses and flickering lights): each of 16 × 9 areas of the frame (or the whole frame) is brought to its average brightness over the frames either side, so flicker goes and slow changes such as a sunset stay.
  - **Tilt-Shift Blur** (a miniature look: a sharp band, with a saturation boost) and **Camera Shake** (smooth random movement and rotation, zoomed just enough that the edges never show).
  - Sizes are in source pixels, so previews and exports match, and what moves is tied to the frame, so a frame always renders the same.
- **Object Removal**: Effects › Refine › Object Removal paints out whatever its mask covers (a drawn shape, an object picked and tracked with an Object mask, or the People shape) and fills it with what plausibly lies behind, using LaMa (Apache-2.0, 208 MB, downloaded the first time). The area round the mask is worked on at 512 x 512, so small things like a logo, a sign or a passer-by keep their surroundings' detail; Grow Mask takes in their edges. Each frame is filled on its own, about 3 s a frame on four CPU cores, so render it, and expect some shimmer where the fill has to invent a lot on moving shots.
- **Restoration** (Effects › Repair; no AI model, for film scans and dirty sensors):
  - **Dirt Removal** finds specks that are on one frame only: lighter or darker than the same place in the frames either side (followed along the motion) while those two agree, and no larger than Largest Speck. It fills them from those frames. Specks that last two frames are then found against the frames two away and filled from those. Show Detected marks what it found in red. A small object moving fast can be taken for dirt; a mask keeps the effect off it. Dirt Removal and Dust Spot Removal work on video and picture files (not nested sequences or generators), on whole source frames (the in-between frames of slow motion are left as they are made).
  - **Frame Repair** (Clip › Repair Damaged Frames…, or MCP `montage_find_damaged_frames`): the selected video clips' files are read over the stretch each clip plays, and every broken frame is found: ones the decoder reports damaged, frames missing from the file's timestamps (shown as a repeat), a lone black or white flash frame, tape drop-out lines and blocky digital hits. Each frame is compared with the picture the frames either side make between them along their motion, so movement, cuts and a real camera flash are left alone. The frames are listed on the clip's Frame Repair effect, which rebuilds each from the nearest good frames (with the AI slow-motion model when it is installed), only the broken lines or patches for a drop-out or hit, and each gets a red "Damaged:" marker. Show Repaired tints what was replaced.

Inside the spot, what differs from the neighbouring frames is replaced from them, so a mark on a moving picture keeps its detail; Clear This Frame and Clear All take the marks away. Spots and strokes are placed on the picture as the clip's own transform shows it, so mark a clip before stabilising, straightening or reframing it, or with those effects off. Razor cuts and trims keep them on their frames.
  - **Scratch Removal** finds thin vertical lines lighter or darker than both sides, the same way down most of each eighth of the frame (so a scratch may come and go), up to Width pixels wide, and fills each row across them. Polarity limits it to dark or light scratches. Follow Slanting Scratches (on by default) also finds scratches that lean or wander a pixel a row, followed down the frame row by row.
  - **Patch Fill** covers its mask (a shape, a drawn path or a tracked mask) with the picture Source X / Source Y away, blended by its gradients so its light matches the surroundings and no seam shows (Seamless), or copied as it is.
  - **Paint (Clone and Heal)**: arm it from the Inspector (Paint on the Monitor), Alt-click where to copy from and paint over a rig, a logo or a boom shadow. Clone copies, Heal blends by gradients like Patch Fill. A stroke is for that frame or the whole clip, and with Strokes Follow the Mask Track it moves with the effect's tracked mask (the mask does not limit the strokes; it is only what they follow). Each stroke is one undo step; Esc stops painting.
- **Film scans** (Effects › Film, on video and picture files; Color Correct's printer lights). The Film effects run on the source frame before anything else in the clip's stack, whatever their place in it: Steady on Perforations first, then Film Negative, then Faded Colour Restore.
  - **Film Negative** turns a negative scan into the picture: each channel's density above the film base (on colour negative its orange mask) becomes light as printing density's standard conversion has it (reference white 685, black 95, the negative's gamma), with a print exposure in stops. The scan can be read by its own curve, as linear light, or as 10-bit log printing density. The base is found in each frame (the clearest film there, the perforations left out), or **Take the Base From This Frame** in the Inspector sets it for every frame from the frame under the playhead.
  - **Printer lights** on Color Correct (R, G, B in points; a point is 0.025 log exposure, which is a setting): in the Colour workspace, on the numeric keypad 7, 8, 9 add a point of red, green or blue, 4, 5, 6 take one away and + and − move all three, on the graded clip (a Color Correct is added when it has none). A run of presses is one undo step, and the status bar shows all three.
  - **Faded Colour Restore** brings faded dyes back: each channel's black, white and middle matched to the channel that kept the widest range, measured over the frames either side within the clip so the shot holds steady.
  - **Steady on Perforations** takes out gate weave: the perforations are found in the rebate (left or right) in every frame, each to a fraction of a pixel, and the frame is moved so they sit where they were on the reference frame (**Set Reference From This Frame** in the Inspector; over MCP the clip's first frame when the effect is added). Show Detected marks the holes.
- **Face Refinement**: Effects › Refine › Face Refinement finds the faces in each frame (YuNet, the model People uses) and touches them up within a soft mask from their outline and landmarks, leaving the eyes and mouth out of it: Smooth Skin takes out small blemishes and texture on skin-coloured areas while keeping edges, and Brighten Eyes, Sharpen Eyes and Lighten Face do as they say. - **Lip Sync** (Refine): the largest face's mouth and jaw redrawn to speak another audio track's sound, for a dub or regenerated words, with MuseTalk 1.5 (Tencent Music Entertainment, MIT), whisper-tiny (OpenAI, Apache-2.0) and sd-vae-ft-mse (Stability AI, MIT): 3.9 GB, downloaded the first time from the authors at pinned revisions, the networks built from their weights where they lie. It takes about 4 s a frame on four processor cores, so the monitors show it once the frames are rendered (Render In to Out); exports always include it, and signed exports' Content Credentials name it as AI-generated. Dub's "Lip-sync the speaker's picture to the dub" gives it to the picture clips under the dub (MCP `montage_dub` with `lip_sync`; `montage_add_effect` with `lip_sync`). Dub and MCP ask for the consent of the person shown. Only the largest face in the frame is redrawn, each frame on its own.
- **Remove Background**: Effects › Keying › Remove Background cuts the people out of a shot without a green screen, so the tracks below show around them (or keeps the background and removes them). Hair and soft edges are kept; Edge Shift grows or shrinks the cut and Soften feathers it. Any video effect can also be limited to the people in the picture with the mask's **People** shape (invert it to grade or blur everything but them). It uses MODNet (Apache-2.0, 26 MB, downloaded the first time), a portrait model: it finds people, not objects (pick those with an Object mask). About 0.8 s a frame on four CPU cores.
- **Depth**: Depth Anything V2 Small (Apache-2.0, 99 MB, downloaded the first time) works out how near each part of the picture is, from the picture alone. Three effects use it, under Effects › Depth: **Lens Blur (Depth)** keeps one distance sharp and blurs what is nearer or farther (focus, in-focus range, falloff, blur size); **Depth Fog** thickens a colour with distance, thinning with height above a horizon if asked; **Depth Map** shows the depth as grey, for checking it or as a matte; **Relight** adds a virtual light after the shoot: surfaces turned towards it brighten in its colour and those turned away fall into shadow, while surfaces facing the camera keep their light. Their directions come from the depth's slopes, and its direction, height, intensity, shadows, relief and reach (how far back it lights) can be set. Any video effect can also be limited to a range of distances with the mask's **Depth Qualifier** (from far to near, with softness), so a grade can touch only the background or only the subject. The depth is worked out once per frame from the clip's source picture (about a second a frame on four CPU cores), so render with Render In to Out for real-time playback.

Analyse Depth (in the Inspector, under a depth effect on a video clip) runs Video Depth Anything Small (Apache-2.0, 116 MB, downloaded the first time) over the clip, 32 frames at a time, so a surface keeps its depth as the camera moves. The analysis is kept with the cache (up to 20 GB, the analyses longest unchanged removed first) and every depth effect on that footage uses it (about 2 seconds a frame on four CPU cores, once); analysing another clip of the same file keeps the first clip's analysis too.
  - **Follow Focus** (Lens Blur (Depth)): Point, Object or Face keys Focus Depth so the focus stays on what it follows through the clip: the point at Focus Point X and Y tracked from the playhead both ways, the effect's object mask, or the face nearest the point. Each frame's distance is the middle of the target's depth, eased as a focus puller eases it, and held where the target is lost.
- **Sky Replacement** (Keying): the sky is found in each frame (bright, smooth and open to the top of the picture, and far away when Use Depth is on) and replaced by the picture on another track or a gradient, moving with the camera's analysed motion or a 3D camera solve; Match Foreground and Light Wrap tie the new sky in, and View shows the sky matte. Steady Through the Shot (on by default) carries the sky from the frames around each along the picture's motion, so its edge does not flicker on grainy footage.
  - **Synthetic focus** (Lens Blur (Depth)): each pixel is blurred by its own circle of confusion, from how far its depth is from the focus, and the F-Stop scales the blur. The picture is blurred in layers from far to near, each laid over the ones behind it, which are first filled in where the nearer layer covered them. So a near subject's edge blurs softly over the background, the background shows through it, and a blurred background never bleeds over a sharp subject. **Focus On** picks Focus Depth, a **Focus Point** (Pick Focus on the Monitor, then click the subject in the Program monitor), or the **Nearest Face**. With Focus Point X and Y keyed, each click adds an eased key, and between two keys the focus moves in depth from one subject to the other (a focus pull), not across the picture. The aperture can be round or have 3 to 12 blades (turned by Blade Rotation), Anamorphic Squeeze makes the discs taller, and Cat's Eye cuts them toward the frame's edges. The blur is done in linear light, and Bokeh Highlights lifts highlights above the threshold first, so they open into bright discs while in-focus highlights keep their value. Focus Breathing makes the picture up to 4 % larger focused near than far. It takes about half a second for a 1080p frame on four CPU cores.
- **Video Noise Reduction** (temporal and spatial): up to three frames either side are warped onto the frame along the optical flow and averaged where they match it, so moving pictures are cleaned without ghosting; then an edge-preserving pass on luma and chroma takes out what is left, more where the temporal pass could not help. The noise level is measured from each frame, or set by hand. It runs on the source frames before the clip's other effects, and works under a mask (for example only the sky or a face). On a test clip, temporal and spatial together cut the noise by 12 dB, and edges keep 98 % of their contrast. It is heavy: use Render In to Out for real-time playback.
- Corner Pin: four keyframeable corners map the picture onto any quadrilateral, for screen replacements. The corners show in the Program monitor to drag onto the surface.
- **Mesh Warp** bends a shape or a figure by pins placed on it, the rest staying as rigid as it can. A mesh covers the picture's alpha (or the whole frame). In the Inspector choose the pin kind, press **Pins on the Monitor** and click the Program monitor. **Position** pins are dragged (keyed where they are keyed) or tracked through the shot with **Track Position Pins**. **Stiff** pins keep an area in shape. **Bend** pins turn and scale the area round them. **Overlap** pins say which part is in front where the picture folds over itself. Motion blur follows the mesh. **Grid Warp** drags the points of a grid of rows and columns, the picture following smoothly or straight between them. - Tracking and stabilisation (built in; no OpenCV):
  - **Stabilize** effect: analyses the clip's camera movement when added, then smooths it (or locks the shot). It can correct position, scale and rotation, and zooms to keep the edges hidden. Smoothness can be changed at any time without analysing again.
  - **Camera Gyro** (a Stabilize method): many cameras record their own gyroscope and accelerometer readings. When the clip has them (GoPro's GPMF track, a CAMM track as some 360° cameras and phones write, or a `.gcsv` log, as phone motion loggers write, beside the clip with the same name), Analyze lines them up with the picture's movement (the time offset to within a few milliseconds, which way round the sensor sits, the lens's focal length from points followed across the frame) and Stabilize switches to Camera Gyro: each frame is turned in 3D to a smoothed orientation, each row by where the camera pointed as that row was read (the readout from the data, or Rolling Shutter), and Horizon Lock levels the horizon from gravity. Gyro Offset nudges the timing. It is offered only once data has been found and lined up; footage the camera already stabilised itself does not match its gyro and is left to the measured method. Not yet: Sony, DJI, Canon and Blackmagic RAW motion data, and lens distortion (put a wide lens's correction before Stabilize). On a synthetic camera shaking in three axes with a 60 % rolling shutter, the held, levelled view is within a few percent of a still level camera's; on GoPro's HERO5 sample clip the frame-to-frame shake falls to under half.
  - **Rolling Shutter Repair**: pans and shakes on phones, mirrorless cameras and drones lean verticals and wobble, because the sensor reads its rows one after another. The effect measures the camera's movement (as Stabilize does) and moves each row back to where the picture was mid-frame, from the speed around that frame and the readout (the share of a frame the sensor takes: about 30–60 % for phones, more for many mirrorless cameras in 4K). Zoom to Fill hides the moved edges. Stabilize has the same correction as its Rolling Shutter setting, and MCP `montage_add_effect` measures the movement when either is added. On a synthetic pan sheared as a full-frame readout would shear it, the repaired picture is within 40 % of the difference the shear made.
  - **Mask tracking**: ◀ Track / Track ▶ in any mask section follows what the mask covers from the playhead to the clip's start or end. It tracks position, scale and rotation, and writes keyframes.
  - **Planar tracking** (screen replacement): put a picture on the track above a phone, monitor or sign, add Corner Pin, drag its corners onto the surface, and press ◀ Track / Track ▶. The corners follow the surface in perspective and are keyed on every frame. A blank screen is held by its bezel.
  - **Follow**: Transform › Follow ▶ moves a title, graphic or blurred clip with what is under its Position in the footage beneath it, keying position (and scale and rotation if chosen). Anchor offsets it from the point it follows.
  - **3D camera tracking**: add 3D Camera Tracker (Transform) to a clip and press Solve. It finds the camera that filmed the clip, its path and lens, and where the features it followed are in the scene. It stands the scene on the ground most features lie on. The camera has to move, not only turn, over a scene with depth. The tracked points show in the Program monitor, green where they fit. Over MCP: `montage_camera_track` (solve, info, place, export).

The Inspector shows a field for each item of its data (text, choices, numbers, switches), and Render renders its frames ahead. It plays in at the clip's start and out a second before its end (Play Out Before the End), stepping on every Next Step Every seconds if it has steps. Graphics are drawn offline in an installed Chrome, Chromium or Edge (or the one `MONTAGE_CHROMIUM` names), frame by frame on a clock of their own, so renders are the same every time; their frames are kept (up to 2 GB, or `MONTAGE_OGRAF_CACHE_MB`) and rendered again when the graphic or its data changes. Over MCP: `montage_ograf` (info, add, set, render).
  - Under the hood: pyramidal Lucas–Kanade on Shi–Tomasi corners with forward–backward checks, RANSAC similarity fits, and RANSAC homographies fitted against the first frame, so planar tracks do not drift. The camera solve starts from the essential matrix of the keyframe pair with the most parallax (an eight-point RANSAC; pairs a homography explains are passed over). Each further keyframe is fitted to the points it sees. Bundle adjustment then refines every keyframe camera, every point and the focal length together (Levenberg–Marquardt with the Schur complement, Huber weights). It runs from several fields of view and keeps the best.

- Dialogue cleanup (Effects › Audio Filters › Restoration):
  - **Noise Reduction** learns the noise print from the quietest moments of the recording itself, then turns down hum, hiss and room tone by up to the amount you set.
  - **Dialogue isolation** uses RNNoise, a neural network from Xiph, to keep speech and remove everything else, mixed with the original by Amount.
  - **Speech enhancement** uses DeepFilterNet3 (MIT or Apache-2.0, 16 MB, downloaded the first time it is added) to take noise and room out of a voice: in the test it brings the pauses in a noisy recording down by 48 dB, against 14 dB for Noise Reduction. Max Reduction caps how far anything is turned down, for a lighter touch. Keep › Everything but Speech does the opposite and gives the music, effects and ambience with the voice about 8–10 dB down, for a music-and-effects bed.
  - **De-Click** takes out clicks, crackle and scratches. Each is found where the sound departs from what the samples before and after it predict, and only those samples are rebuilt, from the sound either side (least-squares interpolation). In the test, clicks and short scratches on music and on speech come down 40 dB or more while everything else is left exactly as it was.
  - **De-Clip** rebuilds distorted peaks. The clip level is found from where the samples pile up (so soft clipping counts too, or set it by hand), and each run of samples at it is rebuilt from the sound either side by the same interpolation, held beyond the clip level so a peak can only grow. Each side of zero is judged by itself, as a recording with an offset clips sooner on one. When the rebuilt peaks rise past full scale, the whole clip is lowered just enough to bring them under it, so their shape and the sound's dynamics are kept. In the test, speech and a sweep clipped at −6 dBFS come back 11 dB closer to the original, speech clipped at full scale 24 dB closer, and samples that were not clipped are left exactly as they were.
  - **De-Plosive** takes out popped Ps and Bs: a burst under 150 Hz that rises fast and stands well above the voice's own low end has just that low band taken down for its length, so the voice above 200 Hz is untouched (changed by 0.01 dB in the test, with the pops 22 dB down).
  - **De-Wind** takes out wind on location mics. With two mics, wind is what they do not share: each frequency under 600 Hz is turned down by how little the channels agree, allowing for a voice that is louder on one mic. With one mic (or two identical channels) it is the gusts, sudden jumps in the level under 100 Hz. Max Reduction limits how far. In the test, wind on one mic of a stereo voice drops 14.5 dB while the clean mic changes by 30 dB less than the voice's level.
  - **De-Hum** notches out 50 or 60 Hz mains hum and up to 16 of its harmonics, each a couple of hertz wide, so the voice round them is untouched.
  - **Bandwidth Extension** rebuilds the missing top of speech recorded through a phone, a video call or a low-rate codec, with AP-BWE (MIT; one 119 MB model for each pair of rates, downloaded when a clip needs it). The cut-off is found from the speech's long-term spectrum (within 35 Hz in the test) and picks the model; the original is kept below it and the new band crossfaded in above it, only where the speech is. Clips whose role is Music or Effects are left alone. In the test, JFK's speech cut to 4 kHz comes back 6.7 dB closer to the original above 4 kHz at 16 kHz, and 18.6 dB closer between 4 and 7.5 kHz at 48 kHz.
  - **De-Reverb** takes the room out of a recording. The late reverberation is estimated from the sound itself, as what was heard 50 ms earlier dying away at the room's rate, and subtracted; the room's reverberation time is measured from how fast the sound falls after it stops (or set by hand). In the test, speech in a simulated 0.8 s room has its reverberation time found within 3 % and its late reverberation brought down by 2.6 dB relative to the voice, while dry speech passes nearly untouched.
  - **Spectral Repair** (Clip › Spectral Repair…): the clip's sound as a spectrogram (time across, frequency up on a log scale, level as colour). Drag a box around a sound that shares its moment with the dialogue but not its frequencies (a phone, a squeak, a whistle, a siren), let **Find Frequencies** fit the box to what stands out there, then **Heal** it (each frequency brought down to the level heard just before and after, never raised, the original phase kept) or **Attenuate** it by up to 96 dB; tick All frequencies for a cough or a bump. Everything outside the box is left as it was, the edges are feathered so nothing clicks, each repair is an undo step and the picture shows the result. Repairs are kept on the clip in source time, so trims keep them on the sound, and they run before the clip's other restoration. MCP `montage_spectral_repair` takes boxes in timeline seconds, finds the band itself when none is given, or only reports what stands out (`find_only`).
  - **Breath Control** (Clip › Breath Control…, or MCP `montage_breath_control`): the breaths between a speaker's lines in the selected audio clips are found (unvoiced, quieter than the speech and louder than the room, and between the transcript's words when the clip has one) and each is turned down by a set amount with volume keys, so any one can be put back by dragging its keys.
  - Noise Reduction, dialogue isolation, speech enhancement, Bandwidth Extension, De-Click, De-Clip, De-Plosive, De-Wind and Pitch Shift process the clip's whole source audio in the background and cache the result. Playback uses the original audio until the cleaned copy is ready (usually a few seconds); exports always wait for it.
- **Separate Stems** (Clip › Separate Stems…): the selected audio clips' sound split into vocals, drums, bass and the rest (or with piano as a fifth, or just vocals and accompaniment). Each stem is a WAV in the Stems folder beside the project (and the bin), played by a copy of the clip on its own track (Vocals, Drums, Bass, Other), linked with the clip and in sync with it; the clip is muted so the stems replace it, and two seconds either side are separated too, for trimming. It uses Spleeter (Deezer Research, MIT, trained on Deezer's own catalogue; 73 to 183 MB, the authors' release downloaded the first time), on this computer at about seven times real time on four cores; what Montage does is checked against Spleeter's own TensorFlow code with the same weights to 0.0001. `montage-cli stems song.wav [--stems 2|4|5]` and MCP `montage_separate_stems`. A film's finished mix splits instead into dialogue, music and effects (`--stems 3`), on tracks with those roles, so Export's Audio streams choice "The mix, then dialogue and M&E" (MCP `audio_streams: "dme"`) can deliver an M&E for foreign versions. That uses Bandit v2 (Watcharasupat, Wu and Lerch; code Apache-2.0, the English model's weights CC BY-SA 4.0, 447 MB downloaded the first time), about 2.4 times slower than real time on four cores; dialogue comes out cleanest, music and effects less exactly, and short or sparse speech can be taken for effects.
- **Room tone** (the dialogue editor's fill): right-click a gap on an audio track › Fill Gap with Room Tone. The background of the clip before the gap (or after it) is learned from its quiet moments between words, and new sound with the same spectrum, stereo width and level fills the gap, written as a WAV in a Room Tone folder beside the project, so the room never drops out under a cut. MCP `montage_fill_room_tone`.
- Crossfades: equal power or constant gain
- Loudness normalisation to -14, -16, -23 or -24 LUFS (ITU-R BS.1770 / EBU R128 gated measurement)
- **Live loudness meter** under the audio meters while playing: momentary (400 ms), short-term (3 s) and integrated LUFS, loudness range (LU) and true peak (dBTP). The integrated value turns green on the chosen target (EBU R128 -23, ATSC A/85 -24, streaming -14, Apple and podcasts -16), amber within 2 LU, and red otherwise; true peak turns red above -1 dBTP. - Imports anything FFmpeg reads
- Frame-accurate decoding that honours rotation, pixel aspect ratio, colour space and range
- Hardware decoding on by default (Playback › Hardware Decoding):
  - Devices: VideoToolbox on macOS; D3D11VA, D3D12VA, NVDEC or DXVA2 on Windows; VAAPI or NVDEC on Linux.
  - Any stream or device that isn't supported decodes in software instead, and at most 8 streams decode in hardware at once.
- GPU rendering on by default where there is a GPU (Playback › GPU Rendering; builds with Qt 6.6 or later): the Program monitor's frames are composited and graded on the GPU through Qt's RHI (Metal on macOS, Direct3D 11 on Windows, OpenGL on Linux). Decoded frames go up as they are and are converted to the working space there; Color Correct, Curves, Hue Curves, CDL, Color Space Transform, Invert, Black & White, Hue/Saturation, Levels and .cube LUTs, with their shape masks and qualifiers, and grade graphs (nodes, mixers and keys), the transform with its crop and opacity, the 13 blend modes, cross dissolves and the viewer's display conversion all run there, with the CPU renderer's arithmetic, so a frame looks the same either way (within float rounding). A clip with anything else (another effect, a depth or AI mask) is made on the CPU and blended on the GPU; a frame with an adjustment layer, a track matte, Behind People, a stereoscopic sequence or a trim pass renders on the CPU as before. Exports always render on the CPU. `MONTAGE_GPU=off|opengl|metal|d3d11|d3d12|software` picks the backend, `MONTAGE_GPU_LOG=1` says why frames fall back, and `montage-cli bench --gpu` times it.

A model a device cannot take, or fails while running, runs on the processor instead (Devices… lists the devices and how many models fell back, and why); models run a frame or a word at a time (speech enhancement, translation, cloned voices) stay on the processor. Execution-provider libraries (CUDA, TensorRT, OpenVINO, QNN, DirectML, CoreML and others built as plugins) dropped into `execution-providers` beside the program or in Montage's data folder are registered at start.   - Import and export SubRip, WebVTT, Scenarist SCC (CEA-608 broadcast captions; pop-on, paint-on and roll-up are read), MCC (CEA-608 and CTA-708 together, with each caption's place and the track's colours), TTML in the IMSC 1.1 Text profile (Netflix and broadcast delivery; DFXP files read too), EBU STL (European broadcast, 25 or 30 fps, Latin text) and Advanced SubStation Alpha (`.ass`, with the track's font, size, colours and box). The format is told by content on import and by extension on export, in the Captions panel, `montage-cli captions` and MCP `montage_captions`.
  - **Subtitle checks and tools**: each caption is checked against reading limits, by default the Netflix Timed Text Style Guide's (20 characters a second, 42 a line, two lines, 5/6 s to 7 s on screen, 2 frames apart; Netflix children's and BBC presets in More › Reading Limits). A ⚠ marks the ones that break them, with why in its tooltip, and a line under the list counts them. **Fix Timing** keeps fast or short captions up long enough to read, into the time after them but never into the next caption, ends each the minimum gap before the next, and closes short pauses. **Shift Captions** moves the selected captions (or all), **Sync to Two Points** retimes the track so two captions land where they should (subtitles made for another cut or frame rate), and **Find and Replace** works on the selection or the track; each is one undo step. MCP `montage_edit_captions` does the same.
  - **Spell check**: misspelt words in captions, titles and transcripts get a red wavy underline as you type; right-click one for suggestions or Add to Dictionary, which puts the word in the project's vocabulary (the same list that prompts speech-to-text). Captions are checked in their track's language and titles in the dictionary chosen under Edit › Spelling (English, US or UK, from SCOWL's word lists, built in; UK English takes both -ise and -ize). Acronyms, numbers and web and mail addresses are left alone. A ⚠ in the Captions panel and Quality Check's Spelling check list the captions and titles with mistakes; MCP `montage_spell_check` checks, learns and forgets words.
  - **Translate Track** (Captions › More): a copy of the track in another language, with the same timings, translated on this computer. Opus-MT models (University of Helsinki, CC-BY-4.0) cover English to and from 18 to 22 languages. A pair without its own model goes through English. Each model is about 270 MB and downloads the first time that pair is used. Also `montage-cli translate subs.srt --to de`.
  - **Dub** (Captions › More, or MCP `montage_dub`; done on this computer): a caption track in any language Opus-MT covers is translated into English, each cue is spoken at its time with an AI voice (Kokoro, a little faster where a cue is short) on a new "Dub (English)" audio track, and the original audio is lowered (18 dB by default) while the dub speaks, as in a voice-over translation. The English captions are kept as a hidden track. With "The speaker's own voice (cloned)" it is spoken in the speaker's voice instead, into any of the 23 languages voice cloning speaks (see Cloned voices).
  - **CTA-708 closed captions**: H.264 and HEVC exports with closed captions carry the track as CTA-708 service 1 (pop-on windows placed where each caption sits, in the track's colours, with accented and typographic characters) beside the CEA-608 bytes, as US broadcast requires; Import Embedded Captions reads 708 back (608 when there is none).
  - The CC button shows captions in the Program monitor. When exporting, captions can be burned into the picture, embedded as a subtitle track (mov_text in MP4/MOV, SubRip in MKV, WebVTT in WebM, with the track's language), or both.
- Interchange both ways with Premiere Pro, DaVinci Resolve, Final Cut Pro, Avid and Nuke:
  - Final Cut Pro 7 XML, FCPXML, OpenTimelineIO and CMX 3600 EDL.
  - Imported timelines find their media (missing files come in offline) and keep links, dissolves, speed changes, titles and markers.
  - **ALE and ASC CDL** (dailies from Media Composer, Resolve, Silverstack, LiveGrade or the lab): File › Import ALE reads an Avid Log Exchange and fills in each matching media item's scene, shot, take, tape, camera, description and comment (rows find their media by source file, by name with or without extension, or by tape and start timecode), and its on-set CDL, which grades every clip of that media (one undo step); File › Export ALE writes the selected media (or all) with their log and CDLs. A clip's CDL is its **ASC CDL** effect (slope, offset and power per channel, saturation, by the ASC CDL v1.2 maths), applied in the working space or in the space it was made in (a camera log, ACEScct: converted there and back exactly). Clip › Import CDL reads .cc, .ccc and .cdl files onto the selected clips (a collection matched by id to each clip's name, file or tape) and Export CDL writes them; EDLs carry each clip's CDL as `*ASC_SOP` and `*ASC_SAT` both ways, and Export LUT from Grade bakes it in. MCP `montage_ale` and `montage_cdl`.
  - **VFX pulls and multi-layer OpenEXR**: Export VFX Pulls writes each chosen shot's source frames, untouched, with handles, as OpenEXR (any of its compressions, HTJ2K and zstd among them), DPX or TIFF numbered from 1001, with a pull list; an OpenEXR pull can carry the source render's other layers (AOVs) and Cryptomattes as they are and the clip's masks as mattes. A multi-layer OpenEXR render plays any of its layers (Inspector › Layer), and a mask can be a **Cryptomatte**: click objects of the render in the Program monitor to add them (Ctrl/Cmd-click removes one), named from its manifest. OpenEXR exports take any of OpenEXR's compressions too. Floating-point pictures (OpenEXR, PFM, float TIFF) keep values above 1 through colour conversion, Color Correct, Curves and the compositor to an OpenEXR export, so a highlight four stops over white brought down reads white rather than clipped.
  - **ACES Metadata Files (AMF)** (from on-set tools such as LiveGrade, Silverstack and Pomfort's, and for VFX vendors): Clip › Import ACES Metadata reads an AMF 2.0 (ACES 1 or ACES 2 transform ids) onto the clips it names, or the selected ones: the input transform sets how the media is read (ARRI LogC3 and LogC4, Sony S-Log3, RED, Canon, Panasonic, Blackmagic, Apple, DJI, ACEScct, ACEScg; video by its inverse output transform), the looks not yet applied become the clip's first effects (its CDL in ACEScct or the space named, CLF or `.cube` look files, the Reference Gamut Compression), which grade the camera's picture by scene light before the display rendering, as dailies do, and the output transform can set the sequence's colour space (Rec.709, sRGB, Display P3, Rec.2100 PQ at its peak, HLG, P3-D65 PQ). Clip › Export ACES Metadata writes one per selected clip, and Export VFX Pulls one beside each shot's frames; a CLF is written beside it for any space ACES has no transform id for. ALEs carry `AMF_NAME` and `AMF_UUID`; MCP `montage_amf`.
  - **Compound and multicam clips** go across too. FCPXML carries both ways compound clips (`ref-clip`, picture and sound as chosen) and multicam clips (`mc-clip`: each angle an `mc-angle`, the angle seen and the angle heard). OpenTimelineIO nests a compound clip as a Stack and FCP 7 XML as a sequence inside the clip item; each reads back as one compound clip with its own sequence. EDL, OpenTimelineIO and FCP 7 XML have no multicam clips, so those exports write the angles' own clips in their place, linked; a clip playing every source's sound takes the sound of the angle it shows.
  - **AAF import** (File › Import Timeline, or MCP `montage_import_timeline`): Media Composer sequences and Pro Tools, Fairlight, Premiere or Resolve AAFs come in as sequences. Picture and sound tracks keep their clips, gaps, source offsets and names; each clip is followed through the AAF's master clip to its file (where the AAF says, else beside it or in a folder below it, else as Media Composer finds its own media: by ID among the OP-Atom files of an "Avid MediaFiles/MXF" folder above it or on a drive; missing files come in offline with their names and lengths). A sound track plays its file's channel, dissolves and crossfades keep their cut points, dissolves to and from a gap and sound fade lengths become fades, Audio Gain and its keyframes become clip gain, constant speed changes (slow motion too) are kept, nested sequences come in as nested sequence clips, and locators become markers. Damaged or hostile files are refused without harm.
  - **Media Composer bins** (File › Import Media Composer Bin…, or MCP `montage_import_timeline` with an `.avb`): a bin's master clips come in as media in a bin of the same name, linked to their files (Media Composer's MXF media found by ID as above, else the file they were linked to or transcoded from, else offline), with their custom columns as metadata (Scene, Take and the like as Montage's own fields); subclips come in as subclips, and each sequence as an AAF of it would, its locators as markers. Effects Montage has no counterpart for are left off and named.
  - **Film counts and lists** (for a cut that goes back to film): feet and frames in 35 mm 4-, 3- and 2-perf, 16 mm and 65 mm in every readout (Playback › Counter; the gauge in Sequence Settings); key numbers read from DPX and Cineon scans' film headers and ALE logs, ink numbers from logs, and both burnt in; File › Export Film Lists… writes cut, optical, dupe and pull lists and a change list from an earlier version, as text, CSV or PDF (MCP `montage_film_lists`).
- Project files are readable JSON (`.montage`) and relink moved media through relative paths
- **Shared projects**, for teams on a shared drive (NAS, SAN, a synced folder):
  - Whoever opens a project to edit it holds its lock (a small hidden file beside it naming them and their machine). Anyone else gets it **read-only**: they can watch, play and export it, it follows each save its editor makes, and edits are refused with a message saying who is editing it. When the editor closes it, **File › Edit Project** takes it over (from what they saved last); Save As always makes a copy of your own.
  - A lock left by a crash or a sleeping machine goes stale after three minutes without a heartbeat (at once when its process is gone from the same machine) and can be taken over.
  - **Productions** (File › Production): a folder of the team's projects (one per reel, episode or editor) in the Production panel, with who is editing each, Open, Open Read-Only and New Project. **Import from Project** brings sequences from any project (even one someone else is editing) into the open one, with the sequences they nest and their media linked where it is.
  - MCP `montage_production` lists or makes a production and `montage_import_from_project` brings sequences across; the agent tools never write to a project someone has open (they say who, and point to the live link).
- Crash safety:
  - Unsaved work is saved to a recovery copy about a second after each edit. After a crash or forced quit, the next launch offers to recover it.
  - If audio plugins were in use, it offers to start in safe mode with plugins disabled.
  - Every five minutes of editing, a timestamped snapshot is kept, the newest 20 per project (File › Open Auto-Save Snapshot).
- `montage-cli` for headless rendering and automation

## Building

Ubuntu 24.04 or Debian with Qt ≥ 6.4 and FFmpeg ≥ 6:

```bash
./scripts/setup-deps.sh                 # installs compilers, Qt 6, FFmpeg dev packages
cmake -S . -B build -G Ninja
cmake --build build
ctest --test-dir build --output-on-failure
./build/src/app/montage                 # the editor
./build/src/montage-cli --help          # the command-line tool
```

Optional libraries are used when found: OpenColorIO (OCIO transforms), lilv (LV2 plugins) and ONNX Runtime (object masks). `setup-deps.sh` installs all three; ONNX Runtime goes to `/opt/onnxruntime` from Microsoft's release archive (point `ONNXRUNTIME_ROOT` at another copy). Content Credentials (C2PA signing and reading) need c2pa-rs: `scripts/build-c2pa.sh` (needs Rust's cargo) builds it into `/opt/c2pa` (or a prefix given, then `-DC2PA_ROOT=`).

On macOS: `brew install qtbase qtmultimedia ffmpeg opencolorio lilv libraw openjpeg libmysofa onnxruntime ninja pkgconf`, configure with `-DCMAKE_PREFIX_PATH="$(brew --prefix)"`, then `scripts/package-macos.sh build` makes the DMG. On Windows, build in an MSYS2 UCRT64 shell with the `qt6-base`, `qt6-multimedia`, `qt6-tools`, `ffmpeg`, `opencolorio`, `lilv`, `libraw`, `openjpeg2`, `libmysofa` and `onnxruntime` packages; `scripts/package-windows.sh build` makes the portable folder and zip, and `packaging/windows/montage.iss` (Inno Setup) the installer.

CMake options:
- `-DMONTAGE_BUILD_APP=OFF` builds only the engine and CLI, without Qt Widgets or Multimedia.
- `-DMONTAGE_BUILD_TESTS=OFF` skips the tests.
- `-DMONTAGE_REQUIRE_ONNXRUNTIME=ON` stops the configure step if ONNX Runtime is missing (release builds use it).
- `-DMONTAGE_WITH_LIBRAW=OFF` leaves out camera RAW stills (LibRaw 0.20+, LGPL-2.1 or CDDL-1.0, linked as a shared library when installed).
- `-DMONTAGE_WITH_THORVG=OFF` leaves out Lottie and SVG import (ThorVG 1.1.2, MIT, is fetched and compiled at configure time).
- `-DMONTAGE_SYSTEM_SQLITE=ON` uses the system's SQLite (built with FTS5, as distributions' are) for the sound library instead of downloading the amalgamation; the system's is also used when the download fails.

The object mask, speaker and visual search tests need their models: `scripts/fetch-models.sh ~/montage-models`, then set `MONTAGE_OBJECT_MODEL=~/montage-models/edgetam-video`, `MONTAGE_SPEAKER_MODEL=~/montage-models/speakers` and `MONTAGE_VISUAL_MODEL=~/montage-models/clip-vit-b32`; the people tests `MONTAGE_FACE_MODEL=~/montage-models/faces`, the depth tests `MONTAGE_DEPTH_MODEL=~/montage-models/depth`, the slow-motion tests `MONTAGE_RIFE_MODEL=~/montage-models/rife`, the background removal tests `MONTAGE_MATTE_MODEL=~/montage-models/matte`, the speech tests `MONTAGE_TTS_MODEL=~/montage-models/tts`, the object removal tests `MONTAGE_INPAINT_MODEL=~/montage-models/inpaint` (the app reads the same variables). The speech tests read `MONTAGE_TEST_WHISPER_MODEL`.

## Using the editor

1. **Import** with `Ctrl+I`, or drag files or folders onto the Media panel or the timeline.
2. **Pick shots.** Double-click a clip to load it in the Source monitor, mark `I` and `O`, then press `,` to insert or `.` to overwrite at the playhead on the targeted tracks. The track buttons in the header set the target.
3. **Cut** with the timeline tools. Drag clip edges to trim, use `B` for ripple trim, `N` to roll an edit point, and `Y`/`U` to slip or slide. `Ctrl+K` adds an edit at the playhead.
4. **Add effects** from the Effects panel. Drag them onto clips, or select a clip and double-click the effect. Tune every parameter in the Inspector; the ◷ button animates a parameter with keyframes.
5. **Mix** in the Audio Mixer, and check levels on the meters and colour on the Scopes.
6. **Export** with `Ctrl+M`.

The first clip placed in an empty sequence sets the sequence's frame size and rate.

## AI agents (MCP)

`montage-cli mcp` is a [Model Context Protocol](https://modelcontextprotocol.io) server, so Claude and other MCP clients can edit with Montage. It works over stdio and speaks both the 2026-07-28 revision and the earlier initialize handshake (2024-11-05 to 2025-11-25).

Its tools work on `.montage` files by path. Each edit is saved at once, and the previous version is kept beside the project as `.bak` for `montage_undo`. The tools can:
- probe media, create projects and list a project's timeline;
- place media, split, remove (with ripple), move, trim and change the speed of clips;
- add titles, effects (including masked ones), transitions and markers (chapter markers too), and list the chapters for YouTube;
- run a delivery quality check (flashing, levels, black, freeze, silence, clipping, loudness) and mark the problems;
- automate a track's fader and pan (mode and points);
- export and import marker lists (CSV, Avid locators, Resolve EDL);
- copy a project with its media to a new folder, whole or consolidated to the parts used;
- list offline media and relink it, by searching a folder or file by file (Replace Footage too);
- hold alternative takes on a clip (auditions), try them in place and keep one;
- transcribe (with speaker labels), translate caption tracks, dub them into English, find spoken phrases in the cut, cut by transcript (phrases, filler words, retakes, long pauses, optionally smoothing the jump cuts), and build a cut from a script;
- find shots by description, and find, name and join the people in the footage;
- generate voiceovers from text or from a caption track;
- log media (ratings, labels, keywords, metadata fields, bins), interpret footage (frame rate, pixel aspect, alpha, fields), make subclips, auto-tag shots, and find media by text or smart-bin rules, optionally saving the rules as a smart bin;
- add shape layers (drawn on if asked), and write AI-upscaled copies of videos and stills;
- make a first mix (roles, levels, dialogue rides, ducking), set up a 5.1 or 7.1 mix and place tracks in it, match voices to a reference, mark a music clip's bars or beats and fit music to a length, duck music under dialogue, match clips' colour to a shot, add adjustment layers, and make a reframed copy of the cut at another aspect ratio;
- return a rendered frame as an image so the agent can check its work;
- render with any preset, with progress, optionally folding surround down to stereo and writing stems;
- export and import EDL, OTIO, FCP 7 XML and FCPXML, import AAF, and export AAF (audio as WAVs, picture linked to the original files).

```bash
claude mcp add montage -- montage-cli mcp      # Claude Code
```
Other clients take the same command in their MCP settings, e.g. `{"mcpServers": {"montage": {"command": "/Applications/Montage.app/Contents/MacOS/montage-cli", "args": ["mcp"]}}}`. Reopen a project in the app to see changes an agent made.

**Agent link: agents on the open project**. Turn on Tools › Let AI Agents Edit This Project, then connect with `montage-cli mcp --live` (Tools › Agent Link… shows the exact command and copies it):

```bash
claude mcp add montage-live -- montage-cli mcp --live
```

Every tool then works on the project open in Montage when its `project` is left out: each change appears at once and is one undo step named "Assistant: …" (Edit › Undo takes it back, and so does the agent's `montage_undo`, which leaves the editor's own changes alone). `montage_live_context` tells the agent what is open: the sequence, playhead, In and Out and the selected clips (ids for other tools), and moves the playhead or selects clips to show a result. Tools run off the UI thread on a copy saved beside the project, one at a time; if the editor changes the project while one runs, its result is not applied and the agent is told to try again. The link is MCP over HTTP on 127.0.0.1 only, with a key the app writes (readable by the user only) to `mcp-live.json` in Montage's configuration folder; HTTP clients can use it directly (`claude mcp add --transport http montage-live http://127.0.0.1:PORT/mcp --header "Authorization: Bearer KEY"`). Requests from web pages on other sites are refused.

**Assistant panel** (Window › Assistant): ask for an edit in your own words ("remove the ums from the interview", "put a lower third for Jane Doe, Director, at 10 seconds", "make a 30-second cut for social") and a language model does it with the same tools on the open project, each change one undo step "Assistant: …". The panel lists each tool as it runs and what it reported, and Stop drops a request mid-way. Montage brings no model: Settings choose Claude through Anthropic's API (the key, or `ANTHROPIC_API_KEY`; Claude also sees frames the tools render) or any OpenAI-compatible chat endpoint (OpenAI, or a local Ollama, LM Studio or llama.cpp server, so nothing leaves the computer), and the model. Requests go only to the endpoint chosen.

## Scripting

Scripts are Lua 5.4 programs that call Montage's tools, the same ones its MCP server gives AI agents: `montage.<name>{...}` runs `montage_<name>` with a table of arguments (or `montage.call("montage_add_title", {...})`), and returns the tool's result as a table (with its message as `message`). A tool's error stops the script with that message and the script's line. `montage.tools()` lists the tools, `montage.args` holds the script's arguments, `montage.project` the project it works on, `montage.json(value)` turns a table into JSON text to print, `montage.null` stands for JSON null, and `print` writes to the script's output. Lua's own libraries are there (string, table, math, io, os; not C modules). Stop ends a script even inside `pcall`.

```lua
-- Markers at every title in the active sequence, named after its text.
for _, track in ipairs(montage.project_info{}.tracks) do
  for _, clip in ipairs(track.clips or {}) do
    if clip.generator == "title" then
      montage.add_marker{at = clip.start, name = clip.text or "Title"}
    end
  end
end
```

In the app, put scripts in the scripts folder (Tools › Scripts › Open Scripts Folder; `MONTAGE_SCRIPTS_DIR` moves it) to run them from Tools › Scripts, or write and run them in Tools › Scripts › Script Console (Ctrl+Return runs). They work on the open project: tools without a `project` argument edit it, `montage.live_context{}` gives the playhead, In, Out and selection (and moves the playhead or selects clips), and a whole run is one undo step named "Script: <name>"; `montage.undo{}` takes back only that run's own step. The window stays responsive while a script runs, and Stop ends it at its next step.

On the command line, `montage-cli script [--project <project.montage>] <file.lua> [arg...]` runs a script headless (a `#!/usr/bin/env -S montage-cli script` line is allowed); tools that take a project get the one named with `--project` when the script names none. Ctrl+C stops it at its next step, a second Ctrl+C at once.

**Panels.** A script can give itself a panel: `montage.panel{title = ..., controls = {...}}` describes it, and the first time the script runs it ends there and the panel opens, docked beside the Script Console. Each button on it runs the script again from the top, and this time `montage.panel` returns what the panel holds (each control's value by its id, and the button as `pressed`), so the rest of the script acts on it, as one undo step. `montage.set_panel{id = value, ...}` shows values back on the panel (a label's value is its text), and the run's last printed line, or its error, shows below the controls. Controls are `text`, `number` (with `min`, `max`, `step`), `slider` (whole numbers), `check`, `choice` (with `choices`), `label`, `separator` and `button`. A panel's script is read again from disk at every press, so edits take effect (a panel whose controls changed is rebuilt, keeping what it held where the controls are still there; new ones bring their defaults). Panels open when Montage closes open again at the next start, where they were: their scripts run only as far as `montage.panel`, with tools refused, nothing run or written, and five seconds at most, so call `montage.panel` first; a script that no longer describes its panel is not opened again. Closing a panel's dock forgets it.

```lua
-- Lower Third: a name and role as a title at the playhead, for as long as asked.
local ui = montage.panel{title = "Lower Third", controls = {
  {type = "text", id = "name", label = "Name", value = "Jane Doe"},
  {type = "text", id = "role", label = "Role", value = "Director"},
  {type = "number", id = "seconds", label = "Seconds", value = 4, min = 1, max = 30, step = 0.5},
  {type = "label", id = "status", text = "Adds the title at the playhead"},
  {type = "button", id = "add", label = "Add Lower Third"},
}}
local here = montage.live_context{}
montage.add_title{text = ui.name .. "\n" .. ui.role, at = here.playhead, duration = ui.seconds}
montage.set_panel{status = "Added " .. ui.name .. " at " .. here.playhead}
```

`montage-cli script` prints a panel's description as JSON; with `--press <button>` (and `--set id=value` for its controls) it runs the script as if that button were pressed, printing what `montage.set_panel` shows (no tool runs before `montage.panel` there, and the app's own tools, such as `montage.live_context`, are not on the command line).

**Python.** A script whose file ends in `.py` is Python 3, run by the computer's own Python (3.8 or later: `MONTAGE_PYTHON` names one, else `python3` or `python` on the PATH), so the packages installed there can be imported, as can modules beside the script. It has the same `montage` module, imported for it: `montage.add_title(text="Hello", at=2)` (keywords, or a dict) runs `montage_add_title` and returns its result as a dict, `montage.call("montage_add_title", {...})` any tool, and a tool's error raises `montage.ToolError`, which the script can catch; uncaught, it fails the script with its line, and the script's own lines of the traceback are printed first. `montage.tools()`, `montage.args` (also `sys.argv[1:]`), `montage.project`, `montage.json(value)`, `montage.panel(...)` and `montage.set_panel(...)` work as in Lua, `montage.null` is `None`, and `print` and `sys.stderr` (and what programs it runs print) go to the script's output. Scripts have no standard input. The Script Console's language choice (Lua or Python) sets what its unsaved script is; an opened or saved one follows its file. Stop ends the Python process. A panel opening again at start-up runs with Python's audit hooks refusing programs, network connections, SQLite files and changes to files (a guard against a script doing them unawares, not a sandbox).

```python
# Markers at every title in the active sequence, named after its text.
import montage

for track in montage.project_info()["tracks"]:
    for clip in track.get("clips", []):
        if clip.get("generator") == "title":
            montage.add_marker(at=clip["start"], name=clip.get("text") or "Title")
```

## Architecture

```
src/core     Project model (value types), keyframes, effect catalogue, edit operations,
             snapshot undo, timecode, JSON project I/O.  No GUI dependencies.
src/media    FFmpeg probing, frame-accurate video decoding, audio decoding and peaks,
             decoder pool and LRU frame cache, scene detection, proxy generation.
src/render   CPU compositor (float RGBA, multi-threaded), effects and transitions,
             title rendering, stateful audio mixer, FFmpeg exporter.
src/app      Qt Widgets application: editor state, playback controller (render thread +
             audio sink), timeline, monitors, inspector, media bin, effects browser,
             scopes, mixer, meters, dialogs.
src/cli      montage-cli.
tests        Qt Test suites: core, render, media, and offscreen GUI integration tests.
```

Notes on the design:
- **Edits** are pure functions over a value-type `Project` (`core/EditOps.h`). Undo stores snapshots, so every edit is undoable without per-command inverse code. Interactive drags re-apply the operation to the state captured when the drag began, so the result depends only on how far the pointer has moved.
- **Rendering** uses 32-bit float, premultiplied RGBA throughout. Filters run in clip space before the fixed transform. Decodes happen at the size the clip occupies on screen, which keeps preview cheap.
- **Playback** renders the newest requested frame on a worker thread and drops late frames. Paused frames always render at full quality.
